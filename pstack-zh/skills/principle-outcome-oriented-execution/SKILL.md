# Outcome-Oriented Execution

优化的目标是预期中可验证的最终状态，而不是保住每一个平顺的中间过渡态。

**为什么这么做。** 硬要让每一个中间步骤都保持完全稳定，往往会催生大量临时兼容代码，最后拖成长期技术债。直接向目标架构收敛，在明确的验证边界上证明正确性。

**核心规则：**
- 终态完整度优先于过渡期稳定性
- 只要中间态的临时破损在计划内、范围可控且可回退，就是可接受的

**护栏：**
- 仅用于有明确阶段边界的计划内重写与迁移
- 提前声明哪些环节允许临时不可用
- 迁移期间对正在改动的活跃区域保持高信噪比检查
- 计划收尾时必须通过完整的静态检查与运行时验证
