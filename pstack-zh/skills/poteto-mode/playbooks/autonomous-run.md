### Autonomous run

**退出条件归你把关。先把完成标准定死，再不停歇地一路推到终点。**

1. 开跑第一轮之前，把退出条件写成可检验的硬判定（例如测试全绿、复现已修通、全部 N 个 PR 合入、像素 diff 归零）。
2. 用 Cursor 内置的 `/loop` 命令选好唤醒机制（`/loop` 是内置能力，不是 `pstack` 的 `skill`）。如果有明确事件可盯（CI 结束、PR 合并、分支推进），派一个监视子代理按事件唤醒你，再配一条较长的定时心跳兜底；如果没有事件可盯，按结果值得复查的间隔设固定心跳。按 `Subagents` 一节给每个子代理挑好推理档位和速度。
3. 每一轮只做证据支持的最小改动，对着退出条件验证；确实向前推进了就提交 commit，没帮上忙的改动直接丢掉。「说不定有用」的保险式改法一律回滚，绝不留着搭顺风车。遵循 **sequence-verifiable-units** `principle`，每干完一小步立刻验证，别攒到最后一块儿查。
4. 跑活中途撞见任何支撑主目标的附带问题，全归你顺手解决：坏掉的 `skill`、关联 bug、不稳定的验证器、评审噪音、工具故障、遗留跟进项、可修复的偏移，全部通过 `poteto-mode` 自己处理。计划外的旁支修复单开独立 PR。不要把可撤回的活停下来丢给人，也别调 `AskQuestion`；只把不可逆操作、实验定不了的真实产品/偏好取舍或真正走不通的死路抛给人。始终盯着主退出条件，每次处理完旁支修复马上回到主线。
5. 每一轮都用 **show-me-your-work** `skill` 记一行 checkpoint，写清改了什么以及退出条件有没有往前走。
6. 退出条件满足时停手。遇到平台期不算到终点，换个思路顶过去；撞上真正的死胡同直接亮出来别原地空转，绝不允许悄悄放宽退出条件来宣布胜利。

**Reply：** 退出条件、总计跑了多少轮、落地了什么、丢弃了什么，以及退出条件的最终状态。
