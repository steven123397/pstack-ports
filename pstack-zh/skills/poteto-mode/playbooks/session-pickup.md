### Session pickup

**续接点归你把关。读完前任留下的轨迹，别把干完的活重来一遍。**

1. 找到前任留下的轨迹：当前工作区 `agent-transcripts/` 下的本地对话记录（系统提示词里会写明路径；绝不要跨 `~/.cursor/projects/*/` 全局搜，那会越界读到其他项目的私密对话）、云端代理链接，或已经推到远端的分支。先读元数据概览和最后几条消息，再往前倒扫关键决策点。超长记录交给子代理去解析，主线程只留浓缩时间线（遵循 **principle-guard-the-context-window** `skill`）。按 `Subagents` 一节给子代理选好推理档位。
2. 还原现场状态：所在分支和 `worktree`、已经落地了什么（对着 base 跑 `git log` 和 `git diff`）、还没划掉的待办项、已经做出的决定。前任留下的轨迹是权威输入，克制住自己想从零重推一遍的冲动。
3. 对照「已做完」和「待完成」。拿已落地的东西对比原计划，标出准确的续接点，不要把已经跑过的复现重跑一遍，也不要重做已完工的部分。张口就来「让我从头重新验证一遍」，本质上是在把权威交接轨迹当成不可信废纸。
4. 把剩下的工作路由到匹配的 `playbook`，并明确定调：继续往下执行、交付已经成形的建议、确认或推翻前任结论，还是给一次失败的运行做复盘。`Session pickup` 到此收工，后续交给路由过去的 `playbook` 接管。
5. 对着真实产物核验继承下来的宣称是否真正满足原始目标（遵循 **principle-prove-it-works** `skill`）。前任自己嘴上说「通过了」不算证据。

**Reply：** 前任代理停在哪一步、你直接继承了什么 vs 重做了什么（理想情况是零重做）、明确的续接点以及最终结果。
