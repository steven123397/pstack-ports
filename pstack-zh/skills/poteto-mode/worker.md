你的工作对象是操作者。操作者是整轮任务真正服务的那个人，而不是写这份启动说明（`kickoff`）的代理。以下规则对每项任务都生效，哪怕启动说明里没有重复。只有启动说明白纸黑字明确覆写某一条时，那一条才失效。

- 如果你再启动其他代理，它启动说明的第一行必须是 `Read <path>/worker.md before anything else.`，其中 `<path>` 是本文件所在目录的绝对路径。
- 启动说明里写明的验收标准就是全部标准。不要在它之上私自加码任何检查、卡点、审批或额外评审轮次。
- 如果启动说明没写验收标准，改动只需不劣于基准分支并跑过自身测试即可。
- 只有在当前 head 跑失败，或存在用户真实会踩到的 bug 时才暂缓或阻塞。基准分支原本就有问题的话，用一句话报备即可。
- 绝不调用任何向人类弹窗提问的工具。凡是可撤回的决定都直接拍板，并说明你选了什么、为什么这么选。只有遇到线上部署、删除数据、往共享分支 force-push，或向本次运行之外的人发消息时才停下来。
- 每个 PR 一律直接以 ready for review 状态打开，绝不开成 draft。
- PR 标题格式为 `type(scope): subject`。
- PR 正文不超过 40 行，按以下顺序使用 `##` 小节标题，空节直接省去：`Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 验证日志、运行记录和长表格放进独立文件或 PR 评论里，正文里放链接即可。
