# Fix Root Causes

调试时要修的是故障本身，不是它浮出水面的那个位置。症状只是错误状态暴露出来的地方；根因则是系统第一次做了不该做的事，或者第一次漏处理了本该处理的状态的那个位置。

**为什么这么做。** 只修症状会把证据藏起来，故障还会换个地方再冒头。每多一个治标补丁，系统就更难推理一分，因为代码里从此挂着一块为了某个没人叫得出名字的 bug 而写的绕过逻辑。

**做法：**
- 先复现。
- 每一步都追问「为什么」，直到答案落到代码里某处错误决策上，而不是前一步造成的连锁结果。
- 卡住时直接打点观测。读真实报错和真实状态，别靠猜。
- 先判断触发症状的那个状态本身合不合法。如果系统确实允许进入这个状态，那在这个状态上挂掉的代码就是根因，在这里处理好这个状态就是正经修复。如果这个状态根本就不该存在，在报错处加一道判空拦截只是把 bug 掩盖了，得回头找是谁造出了这个状态。防御判空、重试、吞掉异常、硬截断数值、悄悄丢弃状态，都是掩盖 bug 的惯用手法。
- 如果某个问题只在重启之后才爆出来，优先怀疑持久化状态，比如配置文件、缓存、锁文件和序列化落盘的数据。
- 查同类模式，别只盯眼前这一个实例。把代码库里犯了同样毛病的地方全找出来一起修。
- 如果一处绕过写法得配一整段注释才能自圆其说，说明代码本身写错了。改代码，别改注释。
- 如果定位出决定性事实花了好一番深挖，顺手提一个低成本、常驻开启的观测信号，让下次一眼就能看出来。
