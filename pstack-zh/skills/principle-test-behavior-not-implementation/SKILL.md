# Test Behavior, Not Implementation

测试本质上是对「代码使用方透过接口能观察到什么」做出断言，包括返回值、报错、能读回来的状态，以及对外部系统的副作用。私有辅助函数、内部调用顺序和中间态数据都属于实现细节。

用两项假想改动检验每条测试：

- **弄坏外部行为**（算错值、漏掉或重复触发副作用）。如果测试照样通过，说明它什么也没证明。常见原因包括断言过于宽松、拿被测代码自己算预期值，或者断言的是测试自己造出来的数据。
- **改写内部实现**但保持所有外部可观察结果不变。如果测试挂了，说明它绑死在了实现细节上。

留住能抓出第一种改动、且扛得住第二种改动的测试，其余的全部重写或删除。通过公开接口传入具体输入来驱动被测代码，并直接从需求推导出预期值。外部服务收到了什么请求属于外部行为，内部辅助函数被没被调用不属于。凡是测「某情况绝不会发生」时，配一条「确实发生」的对照用例。断言调用方赖以分支判断的错误类型，而不是报错文案字符串。
