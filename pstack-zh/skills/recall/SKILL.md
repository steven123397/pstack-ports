# Recall

**在开工或继续推进前，把用户近期的工作上下文重建出来，交回一份紧凑的现状胶囊，说清现在卡在哪、下一步该干啥。**

保持紧凑、紧扣主题。只读范围里相关线索需要的内容，读够就停。

你的上下文分散在两本账里。第一本是你自己的聊天记录，记着你干过什么、拍过什么板。第二本是团队共享记录，记着围绕同一块代码在别处发生的一切，包括用户反复反馈的症状、上线后又被回滚的修复、线上还在持续报的错。这第二本账散落在代码仓库、问题追踪系统、聊天与工单频道、长篇文档和错误监控平台里。一个拖着长长 bug 尾巴的功能，大半故事都在第二本账里，别光靠翻自己的聊天记录硬拼。

聊天记录（transcript）存放在 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是工作区路径去掉开头的斜杠、把每个 `/` 换成 `-` 后的结果（例如 `/Users/you/proj` 对应 `Users-you-proj`）。文件里每一行就是一条对话消息。

1. 先分类，再路由。明确要接续某一段特定历史对话，走的是 `session-pickup` `playbook`，不是本 `skill`。把个人习惯提炼成常驻 `skill`，走的是 `automate-me`。给别人看的工作周报摘要则是另一回事。`recall` 做的是开工前跨近期多段对话装载工作上下文。如果用户已经自己给了完整的现状胶囊（路径、分支、具体改动），直接拿来用，跳过翻记录。
2. 开搜前先锁范围。钉死时间窗口（「最近」必须落成明确区间，默认近 7 天）、用户点名的主题，以及工作区（默认当前活跃工作区，没被要求绝不去翻别的项目的聊天记录）。把锁定的范围复述给用户。绝不要背地里偷偷把「全部」缩水成「最近 N 条」。
3. 在自己的聊天记录里并行扇出检索。挑一个快且便宜的模型派一批并行子代理，每人切一块记录去挖。明确嘱咐每个子代理，按真实修改时间排序（`ls -t`），绝不要按 UUID 名字排；先按主题 grep，只读命中的对话，且只读里面的相关段落；跳过当前对话以及明显噪声（子代理对话、`eval` 对话和测试对话）。每个子代理按同一格式回传，每段对话一块：主题、用户目标、已拍板决定、未了结线索、踩过的坑和纠偏记录，以及产物（PR、工单、分支），每条都标注对话 UUID。如果一共只有一两段对话，别扇出，自己直接查。原始大段聊天记录全留在子代理里，主对话只收汇总发现。按 **poteto-mode** `skill` 的 Subagents 章节，为每个子代理挑选匹配的推理档位。
4. 只要主题点名了某个功能、文件、子系统、领域或 bug，就同步扫一遍共享记录。这是默认动作，不是看心情选做，哪怕用户说的是「我自己在 X 上的工作」也不例外。每个数据源派一个 agent 模式（非 readonly，因为 readonly 会剥离 MCP 权限）的调查子代理，统一问同一个问题：「现状是什么？之前试过什么没扛住？用户现在还在反馈什么？」和翻聊天记录并行跑。查无结果本身也是有效发现。某个 MCP 不可用就跳过并如实说明。把查回来的结果揉进最终 `brief`。只有当用户问的是完全没点名具体目标的纯活动回顾（「我这周干了点啥」）时，才跳过这一步，因为那类问题靠你自己的记录和本地现场就全答完了。
5. 对照真实活现场核验。拿着前面挖出来和扫出来的 PR、分支、工单，直接用 `git` 和 `gh` 查真实状态。如果结论取决于某个代理当时到底干了什么（跑了什么工具、读了什么文件、碰到了什么错），直接读完整的 transcript，别只看裁剪过的本地摘要。
6. 按下面的输出契约写 `brief`。按事项线索分组，紧扣点名的主题。

## 输出契约

开头放现状胶囊，接着列各条线索状态，再列反复出现的问题，最后给下一步动作。更深的细节放下面或直接砍掉。

- **现状胶囊。** 最多 5 条要点，说清这项工作是什么、整体推进到了哪里。
- **线索清单。** 每条线索占一行，开头必须带且仅带一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没贴标签的线索说明还没核实完，补上标签。
- **反复出现的问题。** 最多 5 条，只列反复冒头的。把用户还在持续反馈的症状、以及上线过又被回滚的修复都写进去，让下一棒能接着上一棒栽跟头的地方起步。
- **下一步动作。** 唯一最有价值的下一步具体操作，要落到实处。

相邻的功能或工单除非直接卡住了当前任务，否则一律不放进来。如果胶囊加线索清单超出一屏，先砍细节，别砍线索条目。`brief` 全文过一遍 **unslop** `skill`，聊天记录里的发现标 UUID，共享记录里的发现标来源（PR 号、工单 ID、消息永久链接、错误监控条目）；要发到公开场合前，先把私有上下文脱敏。

**回复要求：** 按上面的输出契约直接交出 `brief`。
