# Model the Domain

把领域逻辑编码进数据结构里，别让它散落在一堆条件分支中。对的数据结构会让非法状态在类型上无法构造，顺手把分支删掉。

遇到散落的布尔值或阶段判断时，换成状态机；遇到松散参数时，换成强类型模型；遇到跨文件蔓延的分支判断时，换成映射表、注册表或可辨识联合类型；遇到东一榔头西一棒槌的就地修改时，换成 reducer；访问模式有特定要求时，选索引、队列或规范化集合。

但别强行套抽象。如果当前形状本来就清晰、局限在局部且大概率不会继续膨胀，就把这种直白朴素的代码留着。凡是只增加间接跳转、却没删掉任何分支或非法状态的抽象，一律保持警惕。

漏用本原则的典型信号是，加一个新需求就得往 `if/else` 链里再塞一条分支，或者必须再加第二个布尔值和第一个手动保持同步。
