# Explain the Number

- **开跑之前先写明决策规则。** 写清什么结果会改变你的决定，以及噪声底线是多少。如果轮次间的波动区间大于效果本身，直接停手。
- **追问「为什么不能再快一倍」。** 拿出运行期间抓到的 profile 或计数器，点出真正卡住上限的资源或代码路径。光看源码猜出来的结论不算瓶颈限制因素。
- **列出这个数字还可能测到了什么**（报错、被跳过或命中缓存的工作、压根没跑到的代码、没调优的对照组、噪声、小到无关紧要的片段），并逐条拿证据排除。
- **汇报数字时必须把运行次数、波动区间和瓶颈限制因素一并带上。**

凡是性能数字，过一遍 [benchmark-checklist](../benchmark-checklist/SKILL.md) `skill`。凡是 `eval` 结果，核查每一轮是否真完成了任务、差距在不同轮次和不同模型间是否稳得住，以及测试场景本身有没有现实意义。
