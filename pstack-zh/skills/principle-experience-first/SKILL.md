# Experience First

当实现省事和用户用得爽发生冲突时，选用户用得爽。

- 每个功能、控件和选项都必须站得住脚，说得出为什么存在
- 少做但做精，三个打磨到位的核心功能，强过十个粗糙功能
- 敲定前先做原型，在用完即弃的 HTML 里试错，成本远低于写完生产代码再改
- 把细节做到位，过渡动画、对齐、间距、操作反馈、报错状态一个都不能凑合
- 收紧核心主循环，每个功能要么服务核心工作流，要么干脆让路删掉

谁消费你的产出，谁就是用户。对 UI 来说是终端用户；对公共库或内部 API 来说是引入它的同事；下一个来维护这段代码的工程师同样是用户。用同样的标准衡量他们的体验，并站在他们的角度说明改动带来的影响。

底层基础要为体验服务。Foundational Thinking 管的是干活的*先后顺序*，这条 `principle` 管的是要奔向的*最终目标*。
