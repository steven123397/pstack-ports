# Build the Lever

只要工作不是一两下就能搞定的琐事，就造一个能干活或能证明结果的工具（codemod、脚本、生成器或可复跑的检查脚本），别纯靠手搓。判断标准是任务是否琐碎，而不是有没有重复。只有寥寥几处一眼看清的改动才跳过造工具。

- 先手工做完第一个单元，再造出工具并在那个单元上重跑验明正身。工具必须支持安全重跑。
- 确定性工具胜过并行扇出。确实需要扇出时，把操作配方、验证契约和硬边界写成一份供委派代理只读执行的 `skill`。
- 只要应用了本原则，产出里就一定有对应文件。如果 `diff` 里既没有脚本、codemod、生成器，也没有委派 `skill`，说明你没真用上。只要工具的寿命超过本次会话，就提交进仓库。
- 只写刚好能完成或证明这件事的最小脚本，绝不顺手造框架。
