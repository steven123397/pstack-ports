# Subtract Before You Add

演进一个系统时，先卸掉复杂度，再动手往上建。默认先做减法。

把简化当成持续投入。每次改完离开时，让底层设计比你接手时更简单、能力更强，同时对外接口面维持不变甚至更小。

- 先排清理删除，再排新功能搭建
- 先精简再打磨，先砍到最小必要范围，再投入精力提质量
- 围绕实际观察到的用法设计，别为臆想的边界情况过度设计
- 规格没要求的校验器、解析器和防御分支，一律不提前写
- 精简 `prompt`，删掉重复指令和过度堆砌的模板
- 某篇参考文档如果已经没有增量信息，直接删掉，别留一个空壳占位文件
